# wrapup

1. 두 가지를 점검한다. 둘 다 코드를 고치지 않는다.
   - A (직접): REQUIREMENTS.md와 구현 비교. 빠진 것 / 요구에 없는데 들어간 것 / 환경에 비해 과한 장치 / 실제 사용자가 쓸 때 막히거나 어색한 곳
   - B (서브에이전트): 실행과 테스트 확인. 실패한 것 / 확인하지 못한 것만 요약해 돌려받는다. 서브에이전트를 쓸 수 없으면 직접 한다.
2. 점검 결과를 보여주고 멈춘다. 무엇을 고치거나 뺄지는 사용자가 정하고, 정한 것은 DECISIONS.md에 기록한다.
3. 결과 문서를 쓴다. 요청에 정해진 파일명이 있으면 그 이름을 쓰고, 없으면 작업계획과판단근거.md로 한다.
   - 목표 / 담당자 요구 요약 / 주요 판단과 근거 / 검증 결과 / 남은 한계 / 다음 단계
   - 판단과 근거는 DECISIONS.md를 기준으로 쓴다.
   - 검증 결과에는 실제로 실행하고 확인한 것만 쓴다.
4. 결정요약.md를 만든다.
   - 주요 결정 5~8개를 한 줄씩: 무엇을 했나 → 왜 했나(담당자 발언) → 어떻게 확인했나 또는 남은 한계
   - 구조 선택 2~3개(파일 구성, 라이브러리, 데이터 저장 방식): 왜 이 방식인지 → 버린 대안
5. 최종 git commit 한다.
