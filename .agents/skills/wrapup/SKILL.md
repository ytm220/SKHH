# wrapup

1. 요청 내용과 내가 전달한 담당자 답을 구현과 비교하고, 실행해서 확인한다. 코드는 고치지 않는다. 빠진 것 / 요구에 없는데 들어간 것 / 실패하거나 확인하지 못한 것을 정리한다.
2. 점검 결과를 보여주고 멈춘다. 무엇을 고치거나 뺄지는 내가 정하고, 정한 것은 DECISIONS.md에 기록한다.
3. 결과 문서를 쓴다. 요청에 정해진 파일명이 있으면 그 이름을 쓰고, 없으면 작업계획과판단근거.md로 한다.
   - 목표 / 담당자 요구 요약 / 주요 판단과 근거 / 검증 결과 / 남은 한계 / 다음 단계
   - 검증 결과에는 실제로 실행하고 확인한 것만 쓴다.
4. 결정요약.md를 만든다.
   - 주요 결정 5~8개를 한 줄씩: 무엇을 했나 → 왜 했나(담당자 발언) → 어떻게 확인했나 또는 남은 한계
   - 알고리즘·데이터 처리와 구조 선택(파일 구성, 라이브러리, 데이터 저장 방식): 쉬운 말 설명 → 왜 이 방식인지 → 버린 대안
5. 최종 git commit 한다.
